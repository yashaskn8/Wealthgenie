# Market runtime configuration: server-only, fail-closed

The server’s optional Upstox adapter reads server-only runtime credentials. In a deployed stack those settings must reach the API container. Compose forwards optional credentials and market-mode flags; Kubernetes uses an opt-in secret reference on the API server.

**No credentials are committed.** Keep all provider and LLM API keys scoped to the API server. Never pass them to Vite variables, frontend source, the ML service, or the agent worker. The base Kubernetes/Kind environment remains `LLM_DEFAULT_PROVIDER=mock`. Only the non-deployable production server overlay overrides this to `LLM_DEFAULT_PROVIDER=api` and `LLM_PRIMARY_PROVIDER=GROQ`; it activates attempted server-side provider selection **only** when authorized credentials are independently provisioned. Missing credentials continue to fail closed, and the ML service/agent worker continue using the base setting. Provider success and cost authorization are not guaranteed by this configuration. Supply secrets only through a private secrets manager, Kubernetes Secret, or local environment. Do not log access tokens.

The default configuration remains `MARKET_DATA_MODE=LEGACY`, `MARKET_DATA_PRIMARY_PROVIDER=NSE`, and `UPSTOX_PUBLIC_MARKET_DATA_LICENSE_CONFIRMED=false`. `UPSTOX_ANALYTICS_TOKEN` and `UPSTOX_ACCESS_TOKEN` are optional; merely setting them does **not** establish source rights, entitlements, historical retention permission, public-display permission or production readiness.

To inspect prerequisites locally, run `npm run market:doctor` from `server/`. Its output is a configuration-only assessment, not proof that an external provider call works. A genuine live-provider test requires valid authorized credentials and source-use permissions. The read-only private demo continues to be separate from any public recommendation or market publication.

The base Kubernetes defaults deliberately retain `LLM_DEFAULT_PROVIDER=mock` for the Kind demo and FastAPI's lightweight test configuration. The production API override does not change ML inference, deploy a live site, or authorize unrelated agent features. Verify actual provider entitlement, request budgets and observed calls before claiming a production LLM integration. GitHub CI and the ephemeral Kind workflow validate behavior independently.
